# TOOLS.md — инструменты сессии

> Что подключено, зачем и где настраивается. Обновлять при изменении `.mcp.json`.
> Решение о составе — `docs/DECISIONS.md`, D-008.

## Сколько стоит инструмент

Главный вопрос при подключении: что попадает в контекст **каждой** сессии,
а что подгружается только при использовании. Механизмы устроены по-разному.

| Механизм | Всегда в контексте | По требованию |
|---|---|---|
| MCP-сервер, обычный режим | имя, описание и **схема параметров каждого инструмента** | — |
| MCP-сервер, отложенный режим | только имена инструментов | схема при первом обращении |
| **Скилл** | **имя и одна строка описания** | **всё тело: инструкции, файлы, скрипты** |
| Плагин | сумма своих частей | |

**Практический вывод.** Скиллы можно подключать заранее: неиспользуемый скилл стоит
одну строку. MCP-серверы — нет: их схемы грузятся целиком и сразу.

**Настоящее ограничение по скиллам — не память, а однозначность.** Чем больше похожих
скиллов, тем выше шанс, что сработает не тот. В каталоге есть минимум три разных
`seo-audit` из разных наборов; подключать все три — гарантированно получить путаницу.
Выбираем один под задачу.

**Плагин — это упаковка.** Из одних скиллов — дёшев. Тащит с собой MCP-серверы
(как `marketing` с ahrefs, hubspot, klaviyo) — платим как за серверы.
Смотреть состав до установки, а не после.

## Скиллы проекта

Решение D-009: эти два набора для «Контент-завода» обязательны.

### `marketing` (Anthropic, knowledge-work-plugins) — включён

Восемь скиллов: `brand-review`, `campaign-plan`, `competitive-brief`, `content-creation`,
`draft-content`, `email-sequence`, `performance-report`, `seo-audit`.

Нужен, когда будем писать промты для статей и постов и сверять их с правилами тона
из `PROJECT.md`. Откладывать подключение не требуется — включённый скилл не грузит контекст.

⚠️ В каталоге плагин числится включённым, но в списке скиллов облачной сессии Claude Code
его скиллы не появились. Похоже, набор рассчитан на другую поверхность.
Проверить командой `/plugin`.

### `superpowers` (obra/superpowers-marketplace) — объявлен, требует установки

Framework методологии разработки. Проверенный состав:

- **тестирование и отладка:** `test-driven-development`, `systematic-debugging`,
  `verification-before-completion`
- **процесс:** `brainstorming`, `writing-plans`, `executing-plans`,
  `requesting-code-review`, `receiving-code-review`, `using-git-worktrees`
- **параллельная работа:** `dispatching-parallel-agents`, `subagent-driven-development`
- **мета:** `writing-skills`, `using-superpowers`

Что важно знать по итогам проверки:

1. **MCP-серверов не содержит** — цена по контексту низкая, это набор скиллов.
2. **Ставит собственный SessionStart-хук.** У проекта уже есть свой
   (`.claude/hooks/session-start.sh`). Несколько SessionStart-хуков сосуществуют,
   их выводы складываются — конфликта быть не должно, но проверить в первой же сессии
   после установки: наш блок «КОНТЕКСТ ПРОЕКТА» должен остаться на месте.
3. **Сторонний marketplace, не из каталога аккаунта.** Ответственность за содержимое
   не на Anthropic. Плагин известный и популярный, но обновления приходят из чужого
   репозитория — при странном поведении сессии смотреть в первую очередь сюда.

Объявлен в `.claude/settings.json` через `extraKnownMarketplaces` и `enabledPlugins`.

⚠️ **Объявление в настройках проекта — не установка.** По документации Claude Code
плагин из внешнего источника считается неустановленным, пока каждый пользователь
не поставит его себе. В облачной сессии контейнер временный, так что может
потребоваться `/plugin install superpowers@superpowers-marketplace`.
Проверяем в следующей сессии.

## Откуда берутся инструменты

Есть три уровня, и это важно различать:

| Уровень | Где живёт | Кто видит |
|---|---|---|
| Аккаунт | настройки claude.ai | все ваши сессии, но не чужие |
| **Проект** | **`.mcp.json` в репозитории** | **все, кто открыл репозиторий, где угодно** |
| Облачная сессия | предоставляет сама платформа | только облачные сессии |

Проектный уровень — единственный, который переживает смену сессии и едет вместе
с репозиторием. Поэтому всё, что специфично для «Контент-завода», живёт там.

## Что сейчас в `.mcp.json`

### `n8n-mcp`

Построение и проверка workflow n8n. Знает ноды, их параметры и умеет валидировать
workflow до заливки на сервер.

Работает в двух режимах:

- **без ключей** — документация и валидация нод. Работает уже сейчас, VPS не нужен;
- **с ключами** — полное управление workflow на вашем инстансе.

Переменные `N8N_API_URL` и `N8N_API_KEY` заданы как `${VAR:-}`: пока они пустые,
сервер поднимается в режиме документации и ничего не ломает. Появится VPS —
заполняете `.env`, и режим переключается сам, править `.mcp.json` не нужно.

⚠️ **Ключ n8n API в community-редакции даёт полный доступ ко всем workflow,
credentials и логам выполнения инстанса.** Это не «ключ на чтение»,
это ключ от всего сервера. Хранить как пароль.

## Что НЕ в `.mcp.json` и почему

### Context7 — актуальная документация библиотек

Уже подключён на уровне аккаунта и работает в облачных сессиях. Добавлять его
в `.mcp.json` под другим именем нельзя: получится второй экземпляр тех же
инструментов, и модель будет видеть их дважды.

Нужен при работе из локального CLI — тогда добавьте блок:

```json
"context7": {
  "type": "http",
  "url": "https://mcp.context7.com/mcp",
  "headers": { "Authorization": "Bearer ${CONTEXT7_API_KEY}" }
}
```

Ключ — на context7.com/dashboard, положить в `.env` как `CONTEXT7_API_KEY`.

### GitHub

В облачных сессиях предоставляется платформой: чтение и создание PR, коммиты,
CI — всё уже работает, ничего настраивать не нужно. Дублирующая запись
в `.mcp.json` конфликтует с платформенной и требует лишнего токена.

Нужен только для локального CLI. Тогда — официальный GitHub MCP server
и personal access token в `.env`.

### Playwright — визуальная проверка сайтов

Отложен до этапа 2 сознательно: пока сайта нет, проверять браузером нечего,
а описания его инструментов занимают место в контексте каждой сессии.
Добавляем вместе с сайтом.

В облачной среде Chromium уже установлен, отдельно скачивать браузер не нужно.

### PostgreSQL

Отложен. Понадобится, когда придётся разбирать логи выполнения n8n прямо в базе.
До первой такой отладки не нужен: n8n-mcp и веб-интерфейс покрывают повседневное.

## Правило пополнения

Новый MCP-сервер добавляется под конкретную задачу, которая уже возникла,
а не про запас. Каждый сервер — это описания его инструментов в контексте
**каждой** сессии; десять «на всякий случай» подключённых серверов вытесняют
из контекста то, ради чего сессия открыта.

## Секреты

Всё чувствительное — в `.env`, он в `.gitignore`. В репозиторий попадает только
`.env.example` с пустыми значениями и пояснениями. В `.mcp.json` секреты
подставляются через `${ПЕРЕМЕННАЯ}` и в git не попадают.
