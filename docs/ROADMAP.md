## Этап 0.7 — VPS и n8n  `[ ]`

Инфраструктура под этап 1. Решение и обоснование — D-007.

- [ ] Домен и поддомен под n8n (`n8n.<домен>`). Тот же домен пойдёт под сайт в этапе 2
- [ ] Reverse proxy с автоматическим HTTPS (Caddy или nginx + Let's Encrypt).
      Telegram принимает вебхуки только по HTTPS с валидным сертификатом
- [ ] `docker-compose.yml`: n8n + PostgreSQL
      (SQLite по умолчанию хуже переносит ежедневный продакшн и аварийные перезапуски)
- [ ] Сгенерировать `N8N_ENCRYPTION_KEY`, положить в `.env`, забэкапить **отдельно
      от сервера** — без него credentials из бэкапа не восстановить
- [ ] Включить аутентификацию n8n, закрыть порт 5678 файрволом, наружу только через прокси
- [ ] Бэкапы: база + том n8n + `.env`, на внешнее хранилище, не на тот же VPS
- [ ] Проверить объём VPS: n8n + Postgres + позже сайт — от 2 ГБ RAM, комфортно 4
- [ ] Включить n8n Public API, выпустить API-ключ, положить в `.env`.
      Public API есть в community-редакции, но ключ там полномочный:
      доступ ко всем workflow, credentials и логам инстанса
- [ ] Завести `automation/workflows/` и класть туда экспорт workflow в JSON
